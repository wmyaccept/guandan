## 二、主题理解与作品立意

本作品选择的正式主题为 **“市井烟火·百味人间”**。主题说明如下：

> 清晨的菜市场里，摊贩的吆喝声此起彼伏，刚出笼的包子冒着热气；深夜的烧烤摊前，炭火映红了一张张疲惫却满足的脸。一条老街，半城记忆，市井烟火里藏着最真实的人间百态。为记录这份平凡日子里的温度与生机，请以“市井烟火·百味人间”为主题，开展网页设计。

我们将“日常相聚的牌桌”作为主题的切入点。市井烟火不仅在街巷摊铺，也在饭后围坐、朋友相聚的一局牌里。掼蛋既是闲暇时的消遣，也是人与人之间交流、配合和陪伴的方式：有时要自己争先，有时要把机会留给对家，一局牌的乐趣不只在输赢，也在共同参与的过程。

作品尝试把这种生活场景延伸到网页，让身处不同地方的人通过一个房间号坐到同一张牌桌前。我们希望传达的“人情味”，落实在以下体验中：

- **像赴一场饭后小聚。** 首页使用木桌、茶杯、扑克牌与暖色调，配合“饭后无事，凑一桌”的邀请，强调日常休闲而非赌场氛围。
- **对面不是孤立的玩家，而是队友。** 四人两两合作，玩法与机器人策略体现让牌、送牌、接风和共同争先。
- **新手也能坐下来。** 首页及牌桌提供“怎么玩”，配合出牌提示、牌型选择和逢人配标记，减少初次参与的门槛。
- **凑不齐人，也能先开一局。** 空位可补机器人，方便单人体验与练习；真人联机时应先让朋友加入，再补齐剩余空位。新玩家不能直接替换已补入的普通机器人。
- **保留轻松的桌面互动。** 支持送花、砸蛋等互动及出牌音效，增加反馈，不改变游戏胜负规则。

## 三、作品功能与体验亮点

### 1. 从开桌到升级的完整流程

支持创建房间、按房间号加入、开局前换座、补机器人、发牌、出牌与不要、名次结算、升级、下一局进还贡及过 A。牌型校验和状态更新由服务端统一处理，前端同步展示。

### 2. 清晰的出牌反馈与新手辅助

- 手牌选择后由玩家确认出牌；选中上方牌不改变上下层叠顺序，避免盖住下方牌。点“不要”会清除选中状态。
- “滑选”开关默认关闭；开启后可用鼠标或触屏连续划过选牌，从已选牌起滑则连续取消选择，取消手势会恢复之前的选择。关闭后恢复拖动组牌；“组牌”只整理展示，不自动出牌。
- “提示”可轮换建议，最终仍由玩家决定是否出牌。
- 红桃级牌作为逢人配时标注表示点数；存在多个合法解释时由真人选择打法。
- 提供记牌器；自己出完后，可查看队友视角。结算时公开剩余手牌，普通结算亮末游手牌，双下提前结束则亮剩余两家手牌；下一局不继续公开。
- 玩法说明可随时打开、关闭，支持 Esc 与键盘焦点返回；**打开说明不会暂停计时**。

### 3. 三档机器人

| 强度 | 策略特点 |
| --- | --- |
| 简单 | 基础配牌与炸弹保留，较少考虑队友，适合熟悉操作 |
| 中等 | 增加让队友、送牌、紧急拦截与控制牌判断 |
| 强力 | 有计算上限的整手配牌搜索，结合余牌结构、公开信息、控牌收尾、协作与炸弹使用进行决策 |

强力机器人比较多套组合，而不只选择眼前最小的可出牌；还贡时也会考虑保留完整牌型。跟牌时评估弱余牌与后续拿回出牌权的能力，不因对手余牌少就持续耗尽大牌；同时区分普通拦截、敌方即将双下和自己两手收尾等局势。它只使用自身手牌和公开信息，**不读取其他玩家的暗牌**。策略为启发式算法，不是保证最优的全局搜索，也不承诺每次送牌或拦截都判断正确。

### 4. 连续体验与个性化

支持短暂断线或刷新后回座、主动退出后托管、行动超时自动操作，以及牌面缩放、桌布与牌面切换、音效开关。房间信息存于服务端内存，服务重启后不能恢复。

## 四、运行方式与评委体验建议

### 本地启动

环境要求：Node.js 18 或以上、npm。当前项目使用 ES modules，依赖版本由 `package-lock.json` 锁定。

在项目根目录执行：

```bash
npm ci
npm start
```

浏览器打开 **http://localhost:3000**。保持终端运行，停止服务按 `Ctrl + C`。

注意：这是包含实时服务端的网页游戏，**不能直接双击 `public/index.html` 运行，也不能仅部署静态文件**。首次安装依赖需要网络，启动后的页面脚本、样式和当前首页插画由同一服务提供，无外部 CDN 素材加载要求。

### 建议体验路径

1. **首页与新手说明：** 浏览首页场景，打开“第一次来？看看怎么玩”，了解开桌、组队及逢人配。
2. **单人快速体验：** 填昵称 →“开新桌”→选择人机强度 →“补机器人”→“开局”。无需准备其他玩家。
3. **出牌操作：** 选择手牌并点击“出牌”；尝试“提示”“组牌”“不要”，观察当前牌型、级牌与行动提醒。
4. **辅助及互动：** 查看记牌器，调整牌面大小、桌布及音效；点击玩家头像体验桌面互动。
5. **完整规则体验：** 完成一局后点击“下一局”，观察名次升级及适用情况下的进贡、还贡或抗贡。首局不进贡。
6. **真人联机：** 另开一桌，让其他玩家通过同一服务地址和房间号加入。建议使用不同设备或独立浏览器配置，避免同源本地存储的回座信息互相影响。

同一局域网联机时，其他设备访问 `http://主机局域网IP:3000`，并输入房间号；需允许防火墙访问该端口。不同电脑上的 `localhost` 并不指向同一台服务器。公网体验请使用上方由团队补充的在线地址。

### 运行限制

- 真人出牌、还贡限时 60 秒，超时由系统代为操作；机器人另按自动行动节奏执行，不等待 60 秒。
- 所有真人离线后，停止自动行动与计时，房间保留 10 分钟，超时清理；保留期间有人回座才恢复行动调度。
- 服务重启清空房间及对局；无账号系统、数据库或跨重启存档。
- 公网部署需支持 Node.js 长运行服务及 Socket.IO 实时连接；使用 HTTPS 反向代理时需正确转发 WebSocket。

## 八、本项目玩法规则摘要

各地掼蛋规则存在差异，本节以 `server/game/cards.js`、`combos.js`、`engine.js` 的实现为准。**牌的大小按本局级牌动态计算，不按代码中的牌面编号直接排序。**

### 基本规则与牌型

- 两副完整扑克牌共 108 张，四人各 27 张，对家同队；双方从 2 起级，当前庄家队级数决定本局级牌。
- 单张、对子、三张及三带二的三张部分：将本局级牌从自然点数顺序中移出，提升到所有非王牌之上；小王、大王仍高于级牌。其余点数按 2、3、…、K、A 递增。比如打 5 时，2 < 3 < 4 < 6 < … < K < A < 5 < 小王 < 大王；打 2 时则为 3 < … < K < A < 2 < 小王 < 大王。打 A 时 A 就是级牌，不另列一个“普通 A”。
- 红桃级牌为逢人配，可补 2 至 A、可补同花顺，不可变王；单独出时只能算自身。
- 单张、对子、三张按点数比较；三带二只比较三张的点数，所带对子可以是真正的一对王。
- 顺子恰好 5 张，木板恰好三连对，钢板恰好两组三张；连牌按自然阶梯比较，级牌不抬高。
- 支持 A2345、23456、10JQKA，不支持 JQKA2；木板及钢板也支持 A 在低端，如 AA2233、AAA222。
- 炸弹至少 4 张同点数牌。大小顺序：4 张炸 < 5 张炸 < 同花顺 < 6 张炸 < 更多张炸 < 天王炸。相同张数的同点数炸弹按本局点数大小比较，级牌炸最大；同花顺之间按自然连牌顺序比较，不受级牌抬高影响。天王炸为两张小王和两张大王。
- 出牌比较时花色不分大小；但系统整理同点数手牌及分配同点数双贡时，会用花色和副牌编号打破平局。这是实现中的排序约定，不代表花色可以压过同点数牌。
- 普通牌型只能由同类型、同张数且更大的牌压过，炸弹可压普通牌型。多种合法逢人配解释由真人选择；天然同花顺按同花顺处理。

### 出牌、名次与升级

- 首局按座位顺序找到第一位持红桃 3 的玩家先出，不要求首手必须包含红桃 3；每一轮领出（桌面没有待压的牌）都不能不要。
- 其余仍有牌的玩家均不要后，最后出牌者继续领出；若已出完，由仍有牌的对家接风，对家也无牌则顺延。
- 依次出完为头游、二游、三游、末游。头游所在队双下升 3 级、头三升 2 级、头末升 1 级，并成为下一局庄家。
- 双下提前结束本局，其余两家按余牌从少到多排列，张数相同按座位编号排序。
- 到 A 不立即获胜：已处于 A 的队伍拿到双下或头三才过 A，头末继续打 A。

### 进贡、抗贡与还贡

- 首局不进贡。下一局双下时由三游、末游各进一张，大贡给头游；其余情况末游向头游进一张，同队也内供。
- 贡牌为除逢人配之外的最大牌；逢人配不贡。
- 进贡方合计持有两张大王可抗贡；胜方的大王不计入。
- 还贡优先允许非级牌的 2 至 10，没有时才允许其他非级牌；级牌不可还。
- 还贡完成后由进大贡者先出；抗贡时由上一局头游先出。
